# 英雄联盟攻略与战术策略小程序 — 产品需求文档（PRD）

| 项目 | 说明 |
| --- | --- |
| 产品名称（暂定） | 攻略匣 |
| 文档版本 | v0.2 |
| 状态 | 草案，待评审 |
| 平台 | 微信小程序（可后续扩展到其他端） |
| 品类范围 | **仅英雄联盟（League of Legends）**，以召唤师峡谷对局策略为主 |
| 核心价值 | 玩家攻略优先；没人分享时联网检索兜底；每篇笔记可公开或私有 |

---

## 1. 背景与目标

英雄联盟版本更迭快，玩家需要的是「这版怎么出装、怎么对线、怎么打团」，而不是一个空社区。冷启动时几乎不会有人投稿，如果这时搜索是空白页，产品就没有用。

因此查询链路必须是：

1. **先查玩家公开分享**（社区攻略，带作者、可收藏）。
2. **若没有可用分享，则联网检索**公开可引用的英雄联盟策略，整理后展示给用户。
3. 玩家随时可以写下自己的战斗策略，选择 **共享** 或 **私有**。

产品承诺：**任何一次针对英雄/分路/对线的查询，都不应该得到空结果。** 空的是社区，不是整个查询能力。

### 1.1 成功标准（MVP）

- 按英雄、分路、对局关键词查询时，有玩家公开攻略则优先展示。
- 匹配不到玩家公开攻略时，自动发起联网检索并返回可用策略摘要（带来源）。
- 登录用户可创建、编辑、删除自己的攻略，并切换公开/私有。
- 私有攻略仅作者可见，不进公开搜索，也不作为「已有分享」用来阻断联网检索。
- 界面必须区分 **玩家分享** 与 **网络策略**，避免用户误当成社区原创。

## 2. 用户与场景

### 2.1 角色

| 角色 | 说明 |
| --- | --- |
| 游客 | 未登录。可搜索、浏览公开玩家攻略和网络策略，不可投稿、收藏。 |
| 玩家（注册用户） | 微信授权登录。可投稿、设可见性、管理自己的内容、收藏公开玩家攻略。 |
| 运营/审核 | 处理举报、下架违规公开内容；抽查网络策略摘要是否侵权或过时。 |

### 2.2 典型场景

1. **冷启动查询（最重要）**：上线初期没人分享「芮尔辅助怎么打」。用户搜索后看不到玩家攻略，系统自动联网检索，给出本版本出装/符文/对线思路摘要和来源。
2. **赛前速查**：锁定英雄后搜「某英雄 + 分路 + 克制」，先看玩家实战贴，没有再看网络策略。
3. **自己记招**：打完一把把换血、视野、团战站位记下来，设为私有。
4. **分享套路**：把验证过的对线/打野路线设为公开，之后同类查询优先出这篇，不再只依赖网络检索。
5. **版本过期**：网络策略按补丁缓存；新版本到来后旧缓存失效，再次检索。

### 3.1 MVP 必做

| 模块 | 功能点 | 优先级 |
| --- | --- | --- |
| 账号 | 微信一键登录、退出、基础资料（头像、昵称） | P0 |
| 英雄库 | 英雄列表（名字、定位、头像）；按分路筛选英雄 | P0 |
| 查询 | 按英雄 / 分路 / 关键词查询策略 | P0 |
| 玩家优先 | 查询结果先展示匹配的公开玩家攻略 | P0 |
| 联网兜底 | **无匹配玩家公开攻略时，自动联网检索并生成策略摘要** | **P0** |
| 来源展示 | 网络策略标明来源站点、检索时间、对应游戏版本 | P0 |
| 详情 | 玩家攻略详情；网络策略详情（摘要 + 原文入口） | P0 |
| 投稿 | 创建攻略：英雄、分路、类型、标题、正文、可见性 | P0 |
| 可见性 | 公开 / 私有；创建后可修改；默认私有 | P0 |
| 我的 | 「我的攻略」全部 / 公开 / 私有 | P0 |
| 编辑删除 | 仅作者可编辑、删除自己的内容 | P0 |
| 合规 | 投稿须同意社区规范；公开内容可举报；网络内容不整篇转载 | P0 |
| 收藏 | 收藏公开玩家攻略；「我的收藏」 | P1 |
| 手动补检索 | 已有玩家攻略时，仍可点「再查网络策略」作补充 | P1 |

### 3.2 后续迭代（不做进 MVP）

- 评论、点赞、关注作者
- 对局后自动识别英雄并推荐
- 云顶之弈、大乱斗专区（可后置；MVP 只做峡谷）
- 实时克制关系图、出装对比
- 多语言、多端

## 4. 信息架构与页面

建议底部 4 Tab：

```
首页    查询    投稿    我的
```

| 页面 | 说明 |
| --- | --- |
| 首页 | 热门英雄入口；本版本提示；最新公开玩家攻略；搜索框 |
| 查询 | 选英雄 / 选分路 / 关键词；结果分两栏：**玩家分享**、**网络策略** |
| 英雄主页 | 该英雄下的分路入口；玩家攻略列表；若为空则直接展示网络策略 |
| 玩家攻略详情 | 正文、作者、英雄、分路、版本、可见性、收藏、举报 |
| 网络策略详情 | 结构化摘要（出装倾向、符文、加点、对线/打野思路）、来源列表、检索时间、免责声明 |
| 投稿/编辑 | 英雄、分路、类型、标题、正文、公开/私有 |
| 我的攻略 | 全部 / 公开 / 私有 |
| 个人中心 | 登录态、社区规范、意见反馈 |

私有攻略 **不得** 出现在首页、查询、他人页面。非作者打开私有链接时展示「内容不存在或无权查看」，不暴露标题。

查询结果页规则：

- 有玩家公开攻略：上方展示玩家列表，网络策略区默认收起或显示「补充查看」。
- 无玩家公开攻略：不展示空态为主界面，直接进入联网检索 loading，完成后展示网络策略；可附一句「还没有玩家分享，以下来自网络检索。欢迎投稿。」

## 5. 核心业务流程

### 5.1 查询策略（含联网兜底）— 主路径

```
用户发起查询（英雄 / 分路 / 关键词）
        │
        ▼
查询本地公开且已发布的玩家攻略
        │
        ├── 有匹配结果 ──► 展示「玩家分享」
        │                      └──（P1）用户可手动点「再查网络策略」
        │
        └── 无匹配结果 ──► 自动联网检索
                               │
                               ├── 命中未过期缓存 ──► 直接返回网络策略摘要
                               └── 无缓存 / 已过期 ──► 服务端检索 → 摘要结构化 → 写入缓存 → 返回
```

**何谓「无匹配」：**

- 该英雄 + 分路组合下，公开玩家攻略数量 = 0；或
- 纯关键词搜索下，标题/标签/正文无命中。

仅标题弱相关、质量不足的内容 **不算** 有结果（MVP 先按「0 篇公开攻略」判断，降低误判；后续再加质量阈值）。

私有攻略 **不计入** 匹配。即使作者自己搜到了自己的私有笔记，对其他用户仍走联网兜底。

### 5.2 联网检索做什么、不做什么

**做：**

- 用查询条件生成检索词，例如：`英雄联盟 {英雄} {分路} {版本号} 出装 天赋 对线思路`。
- 在服务端检索公开网页（搜索引擎或白名单站点）。
- 抽取并 **改写成结构化摘要**，字段见 6.3。
- 列出 2–5 个来源标题 + 链接 + 站点名，供用户跳转原文（小程序内用 web-view 或复制链接，按微信能力选型）。
- 结果与当前游戏版本绑定后缓存。

**不做：**

- 不整篇搬运他人攻略正文、图片、视频。
- 不把网络摘要伪装成「玩家分享」。
- 不允许用户一键把网络摘要「转存为为自己的公开攻略」（可「据此写一篇」打开空白投稿页，需自己重写）。
- 客户端不直接爬外站（域名、鉴权、封禁风险都在服务端处理）。

### 5.3 发布攻略

1. 未登录则引导微信登录。
2. 选择英雄、分路等必填项（见第 6 节）。
3. 选择可见性：
   - **公开**：进入公开库，可被查询命中，从而减少该英雄/分路对联网兜底的依赖；需过内容安全校验。
   - **私有**：只进作者个人库。
4. 公开成功后，该英雄+分路的查询应优先打出这篇玩家攻略。

### 5.4 修改可见性

- 私有 → 公开：等同公开发布，重新走内容安全校验。
- 公开 → 私有：立即从公开查询撤下；若该英雄+分路因此重新变成 0 篇公开攻略，后续查询恢复联网兜底。
- 已收藏该篇的用户：收藏保留但无法打开，提示「作者已改为私有」。

### 5.5 删除

- 作者删除后软删除，查询与详情均不可见。
- 公开内容被删后，他人收藏失效；该维度若再无公开攻略，恢复联网兜底。

## 6. 内容模型

### 6.1 玩家攻略字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| title | 是 | 标题，2–40 字 |
| championId | 是 | 英雄 |
| role | 是 | `top` / `jungle` / `mid` / `adc` / `support` |
| contentType | 是 | `guide` 攻略 / `tactic` 战斗策略 |
| patch | 否 | 对应游戏版本，如 `14.15`；不填则记为发布时的当前版本 |
| tags | 否 | 最多 5 个，如「对线」「克制」「开局」「打野路线」「团战」 |
| body | 是 | 正文，纯文本 + 换行；图片最多 9 张 |
| visibility | 是 | `public` / `private`，**默认 private** |
| status | 系统 | `draft` / `published` / `removed` |
| sourceType | 系统 | 玩家内容固定为 `user` |
| authorId | 系统 | 作者 |
| createdAt / updatedAt | 系统 | 时间 |

公开时二次确认：「公开后所有人可搜到这篇内容，并会优先于网络检索展示。」

### 6.2 英雄与分路（主数据）

只做英雄联盟，不再做多游戏切换。

- 英雄：id、中文名、英文名、定位、头像。
- 分路：上单、打野、中单、下路、辅助。
- 模式（MVP 固定）：召唤师峡谷。大乱斗 / 云顶之弈不做进首发。

英雄数据可配置、可随版本增量更新，不要把全英雄写死在前端。

### 6.3 网络策略缓存字段

| 字段 | 说明 |
| --- | --- |
| queryKey | 规范化查询键，如 `championId + role + patch` 或关键词 hash |
| patch | 检索时的游戏版本 |
| summary | 结构化摘要：核心思路、出装倾向、符文倾向、技能加点、对线或打野要点、注意事项 |
| sources | `{ title, siteName, url }[]`，2–5 条 |
| fetchedAt | 检索时间 |
| ttl | 有效期；建议随版本失效，同版本内 12–24 小时可复用 |
| sourceType | 固定 `web` |

缓存命中条件：同一 `queryKey` + 同一 `patch` 且未过期。版本号变更后旧缓存一律不返回。

## 7. 权限与可见性规则（必须写死）

| 操作 | 游客 | 作者本人 | 其他登录用户 | 审核 |
| --- | --- | --- | --- | --- |
| 查公开玩家攻略 | 是 | 是 | 是 | 是 |
| 触发联网兜底 | 是 | 是 | 是 | 是 |
| 看网络策略摘要 | 是 | 是 | 是 | 是 |
| 搜/看私有攻略 | 否 | 是 | 否 | 仅处理举报时 |
| 创建攻略 | 否 | 是 | 是 | — |
| 编辑/删除 | 否 | 仅自己的 | 否 | 可下架公开内容 |
| 改可见性 | 否 | 仅自己的 | 否 | 否 |
| 收藏 | 否 | 公开玩家攻略 | 公开玩家攻略 | — |
| 把网络摘要存成自己的公开帖 | 否 | 否 | 否 | — |

服务端必须鉴权。私有内容查询必须校验作者身份。联网检索只在服务端执行，接口按查询键限流。

## 8. 非功能与合规

### 8.1 体验

- 有玩家结果时：列表 3 秒内出数。
- 走联网兜底时：先出「正在检索本版本策略…」；目标 8 秒内返回摘要，超时则展示来源链接列表或失败重试，**禁止无限空白页**。
- 同一查询 10 秒内重复请求走缓存，避免打爆检索配额。
- 搜索输入防抖。

### 8.2 内容安全

- 玩家公开 UGC：微信文本/图片内容安全接口，不通过不许公开。
- 网络摘要：入库前同样过文本安全；过滤外挂、脚本、账号交易等内容。
- 禁止侵权整篇转载；网络策略页固定展示：「内容由网络检索整理，仅供参考，版权归原作者，请以游戏内实际版本为准。」
- 禁止外挂、作弊、代练广告。
- 公开玩家内容可举报。

### 8.3 小程序与检索约束

- 外网检索、抓取、摘要全部在云函数/自有后端完成。
- 小程序 request 合法域名只指向自己的后端。
- 外链打开需符合微信 web-view 业务域名规则；若无法打开，提供「复制链接」到系统浏览器。
- 检索需限流（按用户、按 IP、按 queryKey），防止被当免费爬虫网关。

### 8.4 其他

- 登录：微信 `code` 换自定义登录态，过期静默续期。
- 私有正文走 HTTPS，数据按用户隔离。
- 上架前确认微信 UGC / 资讯类目与资质。

## 9. 技术建议（便于开工，非强制）

| 层 | 建议 |
| --- | --- |
| 前端 | 微信小程序原生，或后续要多端再用 Taro / uni-app |
| 后端 | 微信云开发（云函数 + 云数据库 + 云存储）；联网检索必须放云函数 |
| 联网检索 | 服务端调用搜索 API，对白名单域名做摘要；结果写入 `web_guides` 缓存表 |
| 玩家搜索 | 云数据库：英雄 + 分路 + 状态 + 可见性；关键词先做标题/标签匹配 |
| 版本号 | 可配置当前补丁（如 `14.15`），运营手动更新或接口拉取 |

数据集合建议：`users`、`champions`、`guides`、`web_guides`、`favorites`、`reports`、`patch_config`。

查询索引建议：

- 公开玩家列表：`sourceType + visibility + status + championId + role + updatedAt`
- 我的：`authorId + updatedAt`
- 网络缓存：`queryKey + patch`

## 10. 里程碑

| 阶段 | 周期（预估） | 交付 |
| --- | --- | --- |
| M0 评审 | 1–2 天 | 确认检索来源、摘要粒度、当前补丁维护方式 |
| M1 骨架 | 3–5 天 | 登录、Tab、英雄列表、云开发环境 |
| M2 玩家内容闭环 | 5–7 天 | 发布/编辑/删除、公开私有、我的攻略、详情权限 |
| M3 查询 + 联网兜底 | 5–8 天 | 玩家优先检索；0 结果自动联网；缓存与版本失效；来源展示 |
| M4 合规上架 | 2–4 天 | 内容安全、限流、免责声明、举报、类目材料 |
| **MVP 合计** | **约 4–5 周** | 冷启动也可查到英雄联盟策略的小程序 |

M3 是差异化能力，不建议砍掉或放到上线之后。

## 11. 待确认问题

1. **「小程序」是否特指微信？** 当前按微信写。
2. **正文形态**：纯文字 + 图片是否够用。
3. **公开内容先发后审还是先审后发？** 建议 MVP 先发后审 + 机器审核。
4. **联网摘要的粒度**：只给「出装/符文/思路要点 + 来源链接」，还是允许更长的改写？建议前者，版权风险更低。
5. **检索来源白名单**：是否限定中文站（如英雄联盟官网资讯、主流攻略站、视频标题摘要），还是通用搜索引擎。
6. **当前游戏版本谁来更新？** 运营配置 vs 自动拉取。
7. **产品名** 是否用「攻略匣」。
8. **是否包含云顶之弈 / 大乱斗？** 当前 MVP 不含。

## 12. 本期结论（可直接当开发范围）

范围锁定英雄联盟峡谷对局。查询永远按下面这条链工作：

1. **先查玩家公开战斗策略。**
2. **没有人分享时，系统自己联网检索本版本策略并整理展示。**
3. **玩家仍可添加自己的攻略，并选择共享或私有。** 一旦有人公开分享，同类查询优先用玩家内容，网络检索退居补充。

没有玩家内容时产品仍然可用——这是本版本相对 v0.1 最重要的一条。
